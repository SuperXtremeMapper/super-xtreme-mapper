# JSON interchange milestone — 12 September 2026

Implemented on `codex/json-interchange`, starting from `b262263`.

## Delivered

- Dedicated version 1 JSON format, schema, exhaustive field inventory, and external editing guide.
- Original TSI bytes and stable source identities retained in a preservation envelope. Import reparses those bytes to reconstruct trusted opaque state and the original baseline before applying JSON edits.
- Bounded JSON scanning, duplicate-key rejection, structural and semantic diagnostics, and ordinary TSI writer preflight.
- File → Import JSON with asynchronous review and cancellation; accepted imports become new, edited, untitled TSI documents. File → Export JSON publishes separately without clearing document changes.
- Explicit review warnings for writer normalization and inspection-only imports when an edit cannot safely preserve opaque data.

## Boundaries and follow-up

The complex 4.4 fixture contains opaque state that the existing writer cannot safely edit. Its unchanged round trip is exact; unsupported edits remain inspectable with an explicit refusal to save, rather than silently regenerating the file. The 4.5.1 fixture demonstrates a supported native edit.

Pure model/parser/catalog types received concurrency annotations so JSON review can run off the main thread. Existing TSI writing and clipboard semantics were retained. No API credentials or new service dependency are required.

The initial implementation pass did not include Traktor application import or physical-controller validation. The application follow-up below supersedes that limitation for import/display checks only. Controller profiles, explanation/documentation assistance, conversational editing, and AI repair remain later milestones.

See [the editing guide](SXM-JSON-Editing-Guide.md) and [field contract](SXM-JSON-Format.md).


## Traktor application follow-up

Traktor Pro 4 Controller Manager accepted all three demonstration files through Add → Import from disk:

- `native-unchanged-roundtrip.tsi`: generated by the JSON codec round trip, byte-identical to the native 4.5.1 source. All eight mappings loaded; the original long Play/Pause comment and LED options were visible.
- `manual-native-verified.tsi`: all eight mappings loaded; the changed “External native-fixture edit” comment was visible. Traktor exported this device successfully as `traktor-reexport-edited.tsi`. This export is not byte-identical: Traktor rewrites its DCBM MIDI-assignment records on export; the original SXM byte-preservation guarantee applies to the SXM round trip, not a subsequent Traktor export.
- `manual-verified.tsi`: the externally changed command loaded as Cue, Input, Deck A, Hold, channel 1/CC 12.

The current settings file was copied to `/tmp/sxm-json-demonstration/traktor-settings-before-validation.tsi` before imports. Existing controller entries remained listed. Three imported test entries were left available for inspection: native fixture ports show unavailable; the source-free test entry was set to None for both ports.

The MIDI port menus listed only All Ports and Traktor virtual ports, with no physical controller. Import/display checks passed; physical control response, audio behavior, and Euphonia address confirmation remain untested.
