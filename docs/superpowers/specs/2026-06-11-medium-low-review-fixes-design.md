# Medium & Low Review Fixes — Design Spec

**Date:** 2026-06-11
**Source:** The MEDIUM/LOW remainder of the four-subsystem review, deferred from `2026-06-11-critical-high-review-fixes-design.md` (all CRITICAL/HIGH items are merged and pushed; suite 184/0 green at HEAD 6c7f176).

## Problem Statement

The remaining findings don't corrupt data on the happy path, but they degrade robustness: a Traktor file with corrupt frames silently becomes an empty document, voice/API failures surface as opaque status codes, the updater can beachball the UI or strand partial downloads, and the wizard leaks MIDI listening and auto-advance timers across navigation. One TSI item still fabricates data (unassigned mappings gain a CC 0 binding).

## Success Criteria (measurable)

1. Opening a TSI whose DEVS frame is malformed surfaces an error to the user; it never yields a silently-empty document that a save would then wipe.
2. A mapping with no MIDI assignment round-trips with no assignment — no fabricated "ChXX.CC.000" binding.
3. `id(for:)`/`name(for:)` are deterministic for duplicate names ("Loop Out"); round-trip test passes repeatedly.
4. Claude API failures show the API's own error message (parsed from the error body) and time out within 30s; the request model is a current, non-retired Haiku.
5. Keychain save/delete uses a search-only delete query; OSStatus failures are logged, and save works after a prior key exists.
6. A stale SFSpeechRecognizer task (after restart) cannot re-fire `onTranscriptReady`.
7. Wizard: Prev/Clear/tab-switch cancel any pending auto-advance; MIDI listening stops on save completion and window close.
8. Updater: DMG mount runs off the main thread; a failed/partial download is deleted; progress never divides by zero; "0.5-beta" users are offered "0.5".
9. Custom `isDirty` clears on save even if the private "NSDocumentDidSaveNotification" never fires (cleared in the save-completion callback as well).
10. All existing 184 tests stay green; new tests cover items 1–5 and 7–9 where unit-testable, **and item 6**: the stale-task guard is unit-tested through a seam (current-task identity check driven with two task tokens; the delayed-start guard driven by swapping the request before the delay fires) — if no seam is practicable after inspection, the plan must say so explicitly and the guard is review-verified.

## Scope — Findings Addressed

### Chunk 1: TSI robustness (Models/TSI/*)
- **M10** `TSIInterpreter.interpret` returns an empty `MappingFile` when DIOM/DEVS content is malformed (only top-level `parseFrames` throws). **The narrow "no parseable device" check is insufficient — partial loss must also surface:** `parseNestedFrames` currently catches nested parse errors and `break`s, returning whatever parsed so far (TSIInterpreter.swift:652-668), so "DEVS says 2 devices, second truncated" silently keeps one. Fix: (a) `parseNestedFrames` propagates parse failures instead of break-swallowing (truncated trailing garbage after ALL declared frames parsed cleanly may still be tolerated); (b) `interpret` validates the DEVS 4-byte device count against the number of parsed DEVI frames and throws a descriptive error on mismatch. The document layer's existing error propagation surfaces it. A genuinely empty mapping file (zero devices declared, zero parsed) remains VALID and opens. **The same contract extends one layer down:** `parseMappings` must validate the CMAS 4-byte mapping count against parsed CMAI frames and propagate malformed-CMAI failures (today it skips bad frames and returns partials — TSIInterpreter.swift:213-249) so a valid device with a corrupt mappings list cannot silently shed mappings and be saved over.
- **M9** `TSIWriter.midiControlName(for:)` fabricates "ChXX.CC.000" when `midiNote`/`midiCC` are both nil. **Explicit sentinel contract (CMAI's MidiNoteBindingId field is mandatory — "omit the field" is not implementable):** writer emits `MidiNoteBindingId = 0xFFFFFFFF` (the same −1 convention DCDT already uses for unassigned ControlId, TSI-File-Format.md:120) and writes NO DCBM/DCDT entry for the unassigned control; interpreter maps ONLY the sentinel to nil note/cc deliberately; a NON-sentinel binding id that's missing from the DCBM lookup is corruption and must throw (folding into the M10 validation layer), never silently become "unassigned" — otherwise a corrupt DCBM erases MIDI assignments and gets saved over. (Today both cases fall into a fabricated "Ctrl_<id>" name whose parse failure accidentally yields nils.) Round-trip test: entry with no assignment stays unassigned, and a file containing the sentinel does not grow a "Ctrl_…" comment or CC 0 binding.
- **M8** Duplicate command name "Loop Out" (IDs 201 and 2393): `id(for:)` iterates a Dictionary — non-deterministic winner, and these are two DISTINCT Traktor commands (201 in CUE/LOOP beside "Loop In"; 2393 in the advanced-deck block beside "Loop In / Set Cue"), so min-ID canonicalization would silently change a user's mapping from one command to the other. Fix: (a) disambiguate 2393's display name following its section's pairing convention (e.g. "Loop Out / Set", mirroring 2392 "Loop In / Set Cue"; cross-check the CMDR reference table if available) so both IDs round-trip distinctly; (b) keep a deterministic lowest-ID tiebreak in `id(for:)` as a backstop; (c) add an exhaustive test asserting `commandLookup` values are unique (catches any other duplicates now and future) and that both 201 and 2393 survive `name → id → name` round-trips.
- **M7-doc** TSI-File-Format.md FX-target table says FX1–4 = 0–3; code (verified correct against Traktor) uses 4–7. Fix the doc table.
- **Cosmetic from chunk-1 review:** `UInt32(clamping:)` for LED/midi range fields in TSIWriter (hand-edited persisted JSON could otherwise trap); replace skip-log `print` with `Logger` (os.log) in TSIWriter.

### Chunk 2: Voice/API robustness (Services/*)
- **M7** `ClaudeAPIService`: parse Anthropic error bodies (`{"error":{"message":...}}`) and surface the message in thrown errors; map 429 to a clear rate-limit message; set `URLRequest.timeoutInterval = 30`; replace retired `claude-3-haiku-20240307` with `claude-haiku-4-5` (current Haiku per Anthropic docs). Keep the response-parsing contract unchanged.
- **M8** `APIKeyManager`: `SecItemDelete` currently receives the add-query (with `kSecValueData`/`kSecAttrAccessible`) — use a search-only query (class/service/account). Log non-success `OSStatus` from add/delete/load via `Logger`. Test the pure query-construction if extractable; otherwise unit-test `isValidKeyFormat` boundaries and rely on review for Keychain calls (CI has no interactive keychain).
- **M5** `AppleSpeechProvider`: delegate callbacks must guard `task === recognitionTask` so a restarted recognizer's stale task can't finalize an old transcript (double processing). Also remove/guard the 0.3s `asyncAfter` that can start a task on a dead `recognitionRequest` after quick stop→start (capture the request and compare against current before starting).
- **M6** Locked-document divergence: `ContentView.addVoiceMapping` returns nil when `isLocked`, but the coordinator has already appended to `sessionMappings` and reports "Saved!". **The current pipeline cannot carry the result back** — insertion happens later via ContentView's `.onChange(of: savedMappingCount)` (ContentView.swift:232), after the coordinator has already published, cleared, and celebrated. Replace the onChange relay with a result-returning insertion closure: ContentView injects `insertMapping: (MIDIMessage, VoiceCommandResult) -> UUID?` into the coordinator; `saveAndContinue` calls it synchronously, appends to `sessionMappings`/registers the id only on non-nil, and otherwise sets "Document is locked — mapping not saved". The `savedMappingCount`/`savedMapping` published-relay members are deleted (no dual path).
- **L** `APIKeyManager` mutates `@Published userAPIKey` off the main actor. **Do NOT blanket-annotate the class `@MainActor`** — `ClaudeAPIService` reads the key through a synchronous `@Sendable () -> String?` provider from nonisolated code (ClaudeAPIService.swift:80-96, wired in ContentView.swift:42-47), which a main-actor-isolated `activeKey` would break. Fix with a two-tier store: a lock-backed (e.g. `OSAllocatedUnfairLock<String?>` or NSLock-guarded) nonisolated snapshot that `activeKey` reads synchronously from any context, plus a main-actor `@Published` mirror updated for UI observation. `saveAPIKey` writes the lock-backed snapshot synchronously (callers see the new key immediately — a bare `DispatchQueue.main.async` write would return before the key is visible) and then mirrors to the published property on main.

### Chunk 3: Wizard UX correctness (Services/WizardCoordinator.swift, Views/Wizard/*)
- **M6** `previous()`, `clearCurrentMapping()`, `switchToTab(_:)`, **and the terminal paths `cancel()`, `reset()`, `performSave()`, and `saveToDocument()` (which returns early to show the overwrite-conflict alert BEFORE performSave runs — a pending advance must not fire while the alert is open)** must `cancelAutoAdvance()` — a pending advance otherwise fires after navigation, after save completion, or after window close. Belt-and-braces: the auto-advance firing path (or `next()`) gains a `phase == .learning` guard so a stray task can never mutate a completed/cancelled wizard. Tests: pending advance + each action → no unexpected `next()`.
- **M7** `performSave` reaching `.complete` must `stopMIDIListening()`; the wizard window's content view gets `onDisappear { coordinator.cancel() }` (or window-close hook) so closing via the title bar disconnects CoreMIDI and clears callbacks.
- **L10** Conflict detection scans `allMappings` across devices but overwrite-removal touches `devices[0]` only — make both operate on the same scope (devices[0] is where wizard inserts; restrict the conflict scan to it).
- **L9** Remove the dead `channel:` parameter from `toMappingEntry(channel:)` and its misleading call site.
- **(Deferred, documented)** 14-bit CC pairing (M8): real feature work (MSB/LSB correlation windows); out of scope for this pass — recorded as a known limitation in the plan, not silently dropped.

### Chunk 4: Updater & app-shell hygiene (Services/UpdateService.swift, XtremeMappingApp.swift, Commands/EditCommands.swift, Views/MappingsTableView.swift)
- **M6** `UpdateService` main-actor blocking — BOTH paths, not just mount: the class is `@MainActor` and `downloadUpdate` streams bytes with synchronous `FileHandle.write` inside the actor (UpdateService.swift:176, 216-223), so large downloads beachball just like `mountDMG`'s `waitUntilExit`. Move the byte-streaming/file-I/O loop and the `hdiutil` run into a nonisolated/`Task.detached` worker; publish progress back to the main actor (batched, e.g. per-64KB chunk). On download failure delete the partial DMG in the catch path; verify downloaded byte count against `asset.size` before mounting when the asset size is known; non-zero `hdiutil` exit throws (best-effort detach if partially attached).
- **L8** Guard progress division: when `expectedContentLength <= 0` and `asset.size == 0`, report indeterminate progress (no NaN).
- **L10** `parseVersion` must not drop pre-release suffixes silently: treat "0.5-beta" < "0.5" (strip suffix for numeric compare; if numerics equal, release > pre-release). Test: beta user offered the final release.
- **M5** Clear the custom `isDirty` in `SaveCallbackStore`'s save-completion callback too, removing sole reliance on the private "NSDocumentDidSaveNotification" (keep the notification observer as belt-and-braces). **URL-keyed lookup is not a sufficient association** — for untitled first-save / Save As, the SwiftUI document may not yet be registered under the new URL, so `markClean(for: document.fileURL)` can miss. Add an NSDocument-instance association: a static `NSMapTable<NSDocument, TraktorMappingDocument>` (weak/weak) maintained where `backingDocument` is assigned; the save callback resolves the SwiftUI document by NSDocument identity first, URL second. Tests cover the registry association and the markClean-by-instance path (full Save As flow is AppKit-bound; the registry seam is the unit-testable part).
- **M7-rest** `AmberSelectionDelegateProxy.installedTables` accumulates stale `ObjectIdentifier`s forever and a recycled address would be skipped — key by `ObjectIdentifier` but hold via `NSMapTable.weakToWeakObjects` (or prune on window close like `windowDelegates`).
- **L9** `EditCommands` reads `ClipboardManager.shared` in `.disabled(...)` without observation. `ClipboardManager` is ALREADY an `ObservableObject` with `@Published` state — the only fix is observing it from the commands scene (`@ObservedObject var clipboard = ClipboardManager.shared` per SwiftUI Commands constraints) so paste items enable immediately after copy.

## Out of Scope
14-bit CC support (feature); per-word Task delivery ordering in MIDIInputManager (harmless, pre-existing); octave-digit accumulation in note parsing (unreachable in MIDI range); Global-vs-DeckA display collapse (documented design); DMG checksum/signature verification beyond size check (needs release-pipeline support).

## Approach
Four chunks mirroring the subsystem boundaries, same pipeline as the CRITICAL/HIGH pass: TDD where unit-testable (TSI, version compare, wizard state, coordinator session rollback, speech task-identity via seam), review-verified where the OS boundary makes tests impractical (Keychain, hdiutil, Commands observation).

## Alternatives Considered
- **Swallow M10 corrupt-DEVS as today but warn:** still loses data on the next save; throwing is the only safe option and matches the document layer's existing error path.
- **Fix M9 by skipping unassigned mappings at write:** loses the user's partially-built mapping row entirely; writing without a binding preserves it.
- **Pin model to claude-haiku-4-5-20251001 (dated) vs alias:** alias `claude-haiku-4-5` chosen — BYOK users get current Haiku without another retirement cliff.
- **Rewrite EditCommands enabling with NotificationCenter:** ObservableObject is the idiomatic SwiftUI mechanism and removes polling.

## Blast Radius / Rollback
App-target only. Riskiest edits: M10 throw (could reject previously-openable corrupt files — intended), model id change (BYOK billing shifts to current Haiku pricing), EditCommands observation (menu plumbing). Each chunk is one commit; revert per chunk. No format changes: M9 writes a Traktor-legal "no binding" representation.

## Open Questions
