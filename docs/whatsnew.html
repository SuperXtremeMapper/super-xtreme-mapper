September 14, 2026

Your Devices, Together

Multi-device mapping is here, as requested by the community. Thank you for helping shape SXM!

  • Create and edit mappings for several devices in one TSI file. Work on one device at a time, or see everything together with All devices.
  • Open the new Devices panel to switch devices. Use the + button to add one, and the gear beside each device to choose its controller, change its label, and set MIDI ports.
  • Duplicate a device, copy or move selected mappings between devices, or export one device as its own TSI file. Undo is available for device and mapping changes.
  • Keep MIDI Learn focused on the input chosen for that device. You can also prepare mappings offline using saved port names.
  • Enjoy a tidier editor with matching rows and controls, a filter in the mappings header, and IN, OUT and IN/OUT menus that open from the full button surface.

If you use identical controllers, check their input and output port assignments in Traktor after importing.

Identify Your Controller, and Talk to Your Mappings

Name your hardware once and SXM shows every mapping's physical control. The Assistant now takes questions and edits in plain words, by text or voice.

  • Tell SXM which hardware a mapping is for. Open a file and a prompt asks "Which controller is this?" — pick your brand and model, or set it later from the Controller button. This never changes your mapping.
  • A new Physical column names each mapping's real control — Fader 1, Play button, Pot 3 — next to the MIDI numbers.
  • 47 documented controller profiles across Allen & Heath Xone, AlphaTheta / Pioneer CDJ and DDJ, Akai APC and MPD, and more, each labelled Full MIDI, Partial, or Documentation-only.
  • Ask the Assistant a question about your mapping, or describe a change in plain words and review the proposed edit before it applies.
  • Speak to it: tap the mic, move a control while you talk ("make this the volume for deck A"), and it attaches that control. Your words appear live as you speak.
  • A cleaner editor: the Controller entry sits next to the Assistant, and the identify screen matches the rest of the app.

Faster Editing for Larger Mappings

Organise your mappings with fewer repeated edits. Thank you to everyone who shared feedback.

  • Find and replace text across selected comments, with a preview and Undo.
  • Reorder rows in Manual Order using drag-and-drop or Move Up/Down. Modifier columns can shrink to their original compact width.
  • See matching MIDI assignments highlighted in red when selecting a row or assigning a shared control.
  • Bulk-change compatible Hotcue 1–8 Type output commands while keeping MIDI, conditions and LED settings.
  • Clone FX mappings between explicitly chosen units, with clearer explanations for deck-clone exclusions.
  • MIDI Learn keeps valid interaction modes. Loop Size Selector uses correctly encoded, labelled values from 1/32 to 32.
  • Save comment edits and reordered existing rows in supported native Traktor files while preserving unused MIDI definitions and metadata. Other edits retain the existing preservation checks.

September 10, 2026

Your LEDs, Your Colours

More control over your LEDs, and more of Traktor's mapping settings at your fingertips. Thank you to everyone who sent reports and shared feedback.

LEDs and Mapping Conditions

  • Edit Controller Range, MIDI Range, Blend and Output Invert for one OUT row or a compatible selection, with undo
  • Use Hotcue State conditions to give cues, loops and empty pads their own LED rules. A DJM-S7 user confirmed blue and cyan colours, LEDs off after cue deletion, and no flickering or stuck LEDs. Colour values depend on your controller
  • #1: Special conditions — choose Deck Play or Is In Active Loop, with Deck A–D or Device Target, alongside modifiers and Hotcue State conditions
  • #9: Unknown OUT commands — modifier outputs use the correct global target, and Generate Stems is recognised for both IN and OUT mappings
  • Keep condition values, deck targets and LED settings when saving, exporting and cloning mappings. Unrecognised settings retain their original data

Compatibility notes

  • The fixes cover the entries identified in #1 and #9. We did not have the complete original mapping or every unknown identifier. If anything still looks unknown, please open a follow-up with the exact identifier or a small example TSI
v1.0.1
September 9, 2026

TSI Import Compatibility Fixes

Fixes exported mappings being dropped when multiple commands share the same MIDI button.

Mapping Fixes

  • Each mapping now receives its own identifier, protecting multi-command pads, modifiers, and Remix Slot mappings
  • Modifier conditions use the identifiers expected by Traktor
  • Delete Hotcue selections and affected Slot/FX ON and OFF values are encoded correctly
  • Unset hotcue values no longer cause a crash during export
  • Additional FX commands verified in native Traktor exports are available in the command picker

Updating Existing Mappings

  • To repair an affected older SXM file, open the original full mapping and use Export Lossy Converted Copy, then check the copy in Traktor
  • Mappings already removed by Traktor cannot be recovered from its reduced re-export
  • If an older Slot FX OFF setting was saved as ON, select OFF again before exporting

Fast, Safe Deck A Cloning

Select Deck A or Remix Deck A mappings, right-click, and clone them directly to Deck B, C, or D.

Deck Clone

Release Quality

  • Native Traktor target data is preserved when equivalent mappings are created for another deck
  • Clone planning is deterministic across mixed Deck A selections and multiple destinations

Native TSI Preservation & Real-World Compatibility

Open, inspect, transfer, and save real Traktor mappings with stronger protection for native controller data, MIDI assignments, comments, and complex macros.

Native TSI Compatibility

  • Traktor 4.4.x & 4.5.x Imports - Real controller exports now open even when they contain native control types or structures the editor does not yet model
  • Pitch Bend & Paired CC - High-resolution and opaque MIDI assignments are preserved instead of rejecting the complete file
  • Safe Native Passthrough - Unchanged files save byte-for-byte, while unsafe edits require an explicit converted export
  • Command Evidence - FX targets, modifier commands, outputs, and controller assignments are validated against live Traktor 4.5.1 exports

Data Integrity & Resilience

  • Bounded Parser - Malformed, oversized, deeply nested, or conflicting TSI structures fail safely without runaway memory or processing
  • Atomic Saves - Document, wizard, voice, and batch-transfer workflows commit as complete operations instead of leaving partial changes
  • Lossless Comments - Long notes, accented text, Japanese characters, symbols, and emoji survive native import and save
  • MIDI Output Resolution - Note and CC destinations for LED output commands are retained and verified

Workflow Improvements

  • Batch macro transfers now preflight every destination and preserve native command data
  • Wizard and Voice Learn sessions recover cleanly from cancelled saves, conflicts, and delayed input
  • Release builds no longer embed obsolete app bundles inside the application resources
